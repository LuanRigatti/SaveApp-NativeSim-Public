# SaveApp NativeSim — primary flow

Use only for an explicit `$saveapp-nativesim` invocation or direct request to start the SaveApp Simulator. That invocation authorizes the audited one-way mirror publication when needed. Do not ask for an intermediate confirmation when every gate passes. Stop on any failed or ambiguous gate.

## Fixed target

- Public build repository: `C:\Projetos\SaveApp-NativeSim-Public`, `LuanRigatti/SaveApp-NativeSim-Public`, branch `main`.
- Private source: `C:\Projetos\SaveApp`, `LuanRigatti/SaveApp`, branch `main`.
- The public provenance file must name the exact live private source commit. Operate only on these two repositories; the pre-publication snapshot gate may create and remove only its validated, uniquely named `C:\Projetos\SaveAppMirrorValidation-<GUID>` sibling directory.

## Run

The local snapshot gate stores its uniquely named temporary copy as a sibling of the private checkout, then removes it after validation. This preserves the fixed-root security simulation contracts; the public checkout is not modified by the gate.

Run from `C:\Projetos\SaveApp` with PowerShell 7, GitHub CLI authentication, and the installed NativeSim CLI. The private `main` must be clean and equal to `origin/main`; never commit or push it. Before publication, the launcher runs `tests/SaveAppSecurity.Tests.ps1`, which uses temporary local fixtures and a mocked GitHub CLI for its Preflight reuse case; it does not dispatch a workflow or start a session. The mirror publisher then calls `scripts/Test-SaveAppMirrorSnapshot.ps1` before copying or staging anything in the public checkout. That gate builds a temporary snapshot from the same explicit allowlist and verifies its file hashes and `.nativesim-source` SHA, then runs `npm ci`, typecheck, lint, full Jest, native contracts, Expo install check, Expo Doctor and the NativeSim security simulations inside that snapshot. A missing required path, unresolved test import, unsafe file, or failed check stops before public copy/staging/commit/push, Swift Preflight, or NativeSim. The gate does not run Expo prebuild, CocoaPods or Xcode on Windows; those remain macOS workflow checks. The publisher then rechecks both repositories, visibility, exact remotes, destination cleanliness and SHA, allowlist, credential/reference scans, staged paths, fast-forward history, provenance, and post-push equality. It commits and pushes only to the public mirror when files differ. A dirty/unpublished private source, dirty/divergent public checkout, failed test or scan, or unexpected path stops the flow.

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -ExecutionPolicy Bypass -File .\scripts\Start-SaveAppNativeSim.ps1
```

OSLog capture is disabled by default. For a manually tested session with capture, configure these public repository Actions variables on `LuanRigatti/SaveApp-NativeSim-Public` under **Settings → Secrets and variables → Actions → Variables**:

- `SAVEAPP_OSLOG_CAPTURE_ENABLED=true`
- `SAVEAPP_LOG_AGE_RECIPIENT=<valid public age recipient beginning with age1>`

Then run the official launcher with `-CaptureOSLog`. The launcher reads only the two repository variables in memory, verifies that opt-in and switch agree, and never prints the recipient. After NativeSim emits both links, the launcher validates the exact repository, workflow run, initial attempt, public SHA, session-specific transport status, run timestamp, tunnel origin, Actions URL, and complete authenticated Simulator URL. With capture enabled, it returns the links immediately with the explicit state `TRANSPORTE PRONTO — BUILD/OSLOG PENDENTES`; it does not wait for app build, installation, launch, or capture startup, and it stops only its local CLI after handoff. The remote workflow continues. The separate `native-sim-capture/<session>` status remains pending until the fixed app-owned `home.catalog.initialize_started` probe is present in the filtered capture file. A pending or failed capture never changes the meaning of the already delivered transport link and must never be reported as capture-ready. Before manual tests that require recoverable logs, check that exact run and session context for capture success; only that status confirms the probe and active stream. If capture fails or remains pending, the Simulator link may still work, but no recoverable OSLog session is promised. With capture disabled, the launcher validates the workflow exact `SaveApp session ready` signal and does not require OSLog statuses. The capture covers only subsystem prefix `com.luanrigatti.saveapp`; the encrypted artifact contains `manifest.json` and ciphertext, with one-day retention. No raw logs are uploaded. Never place the private age identity in GitHub or either repository.

After the user finishes manual interaction, use the installed `$oslog` skill with the exact run ID and `-Profile SaveApp -Stop`. It invokes the shared Emporio collector's controlled status signal, validates the exact SaveApp run/attempt and artifact, verifies the ciphertext checksum, decrypts locally, and uses the existing OSLog exporter. The launcher returns after delivering the session links; it does not wait for user testing or stop the workflow. Disable the repository opt-in after the intended capture window. This integration is local/static until a future authorized mirrored NativeSim run confirms the Actions variables, encrypted artifact, controlled stop, and recovery end to end.

The launcher reuses an active or successful Swift Preflight only when the GitHub repository, workflow path, `workflow_dispatch` event, `main` branch, exact public SHA, and success conclusion all match. Otherwise it dispatches once and waits for that SHA to pass. A failure blocks NativeSim. It then rechecks source/mirror SHA and provenance, refuses any active NativeSim run on `main`, and starts the installed `native-sim.ps1` CLI with the validated iPhone 17 Pro, SaveApp scheme, public tunnel, `--export`, and default `--minutes 120`. The launcher verifies the installed CLI maps `--export` to the workflow input `export_app=true` and prints both links before entering its local artifact wait. A requested valid `-Minutes` value from 1 through 350 is honored.

The Swift Preflight validates the Expo SDK 58 `expo-widgets` pin, effective plugin options and App Group in the resolved app config, Expo iOS autolinking for `ExpoWidgets` and the local Swift modules, and the generated `ExpoWidgetsTarget` project, Live Activities plist keys, and App Group entitlement files for both app and extension. It compiles an unsigned Simulator app and verifies that `ExpoWidgetsTarget.appex` is embedded; this is a build-integration check only and does not confirm that each Xcode target uses its generated entitlements file for signing.

The NativeSim Simulator workflow queries Release `CODE_SIGN_ENTITLEMENTS` separately for `SaveApp` and `ExpoWidgetsTarget`, using `xcodebuild -project ios/SaveApp.xcodeproj -target <target> -showBuildSettings -json`. The extension is registered in the app's generated Xcode project, but querying the `SaveApp` scheme did not return its target settings. The verifier requires exactly the requested target in each response, Release configuration, and an effective entitlement path matching `ios/SaveApp/SaveApp.entitlements` or `ios/ExpoWidgetsTarget/ExpoWidgetsTarget.entitlements`. It also checks that both generated files contain `group.com.luanrigatti.saveapp`. After Xcode builds the Simulator app, the workflow ad hoc-signs only the top-level `ExpoWidgetsTarget.appex` and then the containing `.app`, using each target's generated entitlement file. It does not use `codesign --deep`; nested frameworks and other native components retain their Xcode signatures. Required final gates verify both signatures and extract the signed App Group from each bundle, along with `NSSupportsLiveActivities` and the embedded extension. No Apple certificate or provisioning profile is used. This is limited to the `iphonesimulator` workflow and does not change physical-device signing; a device build still needs Apple Developer provisioning authorizing the App Group. `createLiveActivity` uses the plugin's generated generic Live Activity entry; do not require an app-config `widgets[]` entry. Static and signature checks do not prove ActivityKit authorization, successful container access in the installed Simulator, or Dynamic Island appearance on a device.

The CLI runs in a disposable clone pinned to the public SHA. Its fetch URL identifies the public GitHub repository, while its push URL points to a temporary local bare sink seeded with that same SHA. Before `native-sim up`, the launcher inspects the installed CLI's real scaffold and auto-commit behavior, checks both workflow and gate template versions, verifies `gate.cjs` against the installed template with only the approved `TOKEN` to `GATE_VALUE` rename, and runs the actual scaffold function against the isolated clone. The scaffold must leave workflow, gate, Git status, and HEAD byte-for-byte unchanged. The launcher checks the same file hashes, clone SHA, clean status, and local push sink again after CLI output. The workflow must be active and compatible; never modify the global CLI or workflow to make a run proceed.

The CLI's output is captured privately in memory. Return the full GitHub Actions URL and the exact authenticated Simulator URL printed by this invocation, including the complete `k` value. Never reconstruct, shorten, log, or save that authenticated URL/key. Confirm the run ID, `main`, exact public SHA, Preflight outcome, 120-minute (or requested) duration, and one-time initial workflow/build status. Persist only the CLI's validated non-secret session metadata under the public checkout's Git metadata when available.

As soon as both links and run identity are verified, terminate only the local CLI process tree and return, before its separate artifact wait/download. GitHub Actions continues the same build, exports and uploads the `.app.tar.gz`, installs and opens SaveApp, then keeps the stream available for the requested session duration. Do not wait for any of those remote steps or poll logs. If an active NativeSim run already exists, stop and report its Actions link without attempting to recover or invent its key. For later artifact retrieval, use `$saveapp-simulator-archive`; it can download as soon as that run's build, export, and upload steps succeed, even while the 120-minute stream remains active.
